# Sidepanel progressive reading (#151)

The existing Send action selects one task on the already selected local workspace. The sidepanel now reads that task's completed partial sections while generation continues. Generated sections say “Draft · Evidence pending · Unverified.” The persisted source outline appears first as “Source excerpts · Not an AI summary · Unverified,” using its existing IDs and literal excerpts. Final task completion does not relabel those drafts as verified. The existing workspace remains the place to confirm processing, cancel it, and review final evidence.

## Runtime boundaries

- `extension/sidepanel-progress.js` owns one reader and at most one SSE connection. Event IDs only advance; duplicate/out-of-order events cannot repaint. Replayed failure, cancellation and missing-task events trigger current snapshots, and never directly stop a retried task. Rejoin uses the accepted cursor, and task snapshots cover missed events.
- The selected backend, task and source remain bound together. Changing sources or processing modes releases pending requests and streams. A late task-creation response cannot bind to a different source or newly discovered workspace.
- HTTP reads are single-flight, abortable, timed out after 10 seconds and bracket the partial projection with source/retry/status/options/artifact snapshots. Ordinary progress timestamps do not invalidate completed content, so repeated progress events cannot starve its display. Closed stream callbacks, older attempts and replaced task reads cannot repaint.
- A connection can be attempted at most three times per visible reading session. Snapshot fallback uses a five-second cadence; a healthy stream has a 15-second snapshot safety check. Five failed reads pause the reader until explicit retry or visibility restoration.
- Hidden panels and page suspension close streams and abort reads. Resuming immediately resynchronizes from the cursor. Cancellation-requested, cancelled, failed and completed tasks stop progress reading. The existing subtitle task flow may recover its saved transcript once, with a 10-second timeout and the same frozen binding; closing or switching aborts this recovery, and failure never restarts polling. Restoring a cancelled panel does not revive its progress reader.
- Sections use stable DOM nodes, with unchanged text nodes retained. Adding an earlier section preserves the visible section's offset and text selection. Incoming text uses `textContent` and is kept literal, including markup-looking text, combining characters and user language.
- No new host permissions, backend discovery, credential persistence, extraction or model calls are introduced by the reader. The extension's existing final result path handles completed subtitle tasks.

## Partial API and compatibility

`GET /api/tasks/{task_id}/partial-note` is a read-only projection of persisted partial artifacts. It returns task/attempt/snapshot identity, schema and revisions, explicitly unverified status, and a whitelist of literal section text and source anchors. It never returns internal paths, provider settings or raw diagnostics. Missing, corrupt, foreign, future-schema or unprovable-attempt documents fail closed. Bounded reason codes distinguish waiting, legacy/invalid drafts and short publication races. Existing same-attempt/source sections remain readable during publication; changed attempts/sources invalidate them. A validated source outline remains in place when generated sections arrive.

TaskRecord and the task schema version remain unchanged. The internal partial artifact carries an attempt stamp, so a late completion from an earlier attempt cannot become a current section. Legacy unstamped projections require provable same-attempt provenance before migration. Before any incompatible existing projection is replaced, including an already stamped prior attempt or damaged known schema, its exact bytes are preserved in the task storage directory as `partial_note.previous.<SHA-256-of-original-bytes>.json`. Repeated preservation reuses identical bytes; a missing or failed backup leaves the active projection untouched. Unknown future schema versions remain untouched. These preserved JSON files are local recovery artifacts, not a model cache or an automatically displayed older edition. To recover, retain the file and extract its `sections[].markdown` into a separate unverified draft for inspection; never repoint a current attempt to old stamped content or relabel it verified. The existing final evidence/publication gate remains authoritative.

## Verification and limits

Deterministic Node DOM/transport tests cover literal hostile text, section/selection-node identity, scroll anchoring, duplicate/out-of-order events, cursor rejoin, bounded fallback/retry, visibility, source/task/backend switching, in-flight stale responses, attempt changes, cancellation/failure, and final handling. Integration tests exercise the actual sidepanel task-creation flow.

The Windows `UI visual acceptance` job runs `scripts/sidepanel-progressive-acceptance.cjs` in installed Microsoft Edge with the shipped sidepanel assets. HTTP task replies, EventSource and Chrome APIs are explicitly synthetic. It checks actual browser DOM identity, selection, scroll, reconnect/resume, cancel/failure, source switching, 320-pixel layout, and no unexpected permissions or writes. Its screenshots and report are uploaded under `sidepanel-progressive-ui`.

Local fixture validation uses `node scripts/sidepanel-progressive-acceptance.cjs --self-test`; this does not launch a browser. Actual Edge execution is pending CI for this change. Native Chrome/Edge installation and permission-prompt acceptance remain unverified; synthetic transport is not evidence for those flows. No real course, paid provider, model download or private configuration is needed.
