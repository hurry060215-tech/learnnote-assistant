# 从已保存视频提取画面字幕

在笔记的「更多 → 提取画面字幕」中启动。它创建独立任务，复用已保存视频，不重新下载、不识别音频、不改写原来的 ASR、笔记或个人修订。默认只提取本地 OCR 文字；没有文字模型连接也能使用。勾选「提取完成后生成新笔记」才会在完整提取后，把识别文字发送给当前选定的文字模型，并可能产生模型用量费用。

来源视频保存在来源任务目录时，会用本地硬链接为新任务保留独立文件引用，不复制整片视频；之后删除来源任务也不会破坏这份 OCR 的媒体，尚未裁切的 OCR 子片段也会保留输入引用。若资料目录所在文件系统不支持硬链接，会在创建任务前明确停止。上传目录中的共享文件继续按现有引用保留规则管理。

硬链接是共享只读媒体的文件引用，不是独立字节备份。提取、裁剪、缓存和预览不会原地写入该媒体。用新文件替换来源路径不会改变已保留的媒体；外部程序若原地修改同一文件，哈希不匹配会阻止旧 OCR 恢复或重新生成笔记，不会沿用旧结果。删除来源任务后，媒体空间会保留到最后一个引用被移除。

先预览裁剪位置和识别结果。初始选项是底部 26%、0.5 秒间隔、保留全部文字，适用性取决于当前视频；它们不是准确率保证。四个边界均为画面百分比。语言选项按字形筛选整行，不做翻译：含中文字行 / 含英文字母行 / 全部文字。混合中英的一行会完整保留，未选中的行仍保存在窗口观察记录中。专业词不会被全局替换。

识别结果有每段时间、每行置信度和原画面坐标。相邻完全相同的文字合并；空白间隙和文字变化会分开。时间是抽样估计，短暂出现的字幕可能遗漏；置信度不等于正确率，画面文字也不等于已经核对过的讲者原话。这里只检查所选字幕区域，不理解整幅画面。

## 取消、恢复与完整性

提取逐窗顺序处理，不保存所有视频帧。每 60 秒完成一个窗口后原子写入带校验和的缓存。缓存身份包含完整媒体 SHA-256、裁剪、间隔、语言、处理范围、算法版本、OCR 与解码运行时版本、模型及配置文件哈希。

取消时，当前未完成窗口不会成为有效缓存；恢复会重新校验完整窗口，只补做缺失或损坏窗口。改变设置应创建新任务，不覆盖旧结果。原媒体内容改变会阻止原任务恢复。启动服务后，已有持久队列可继续本地 OCR；若任务带临时文字模型凭据，现有队列规则会要求重新确认模型上下文。

OCR 启动时另外保存媒体身份。汇总结果损坏时，保留损坏文件的逐字节备份，并用这个身份和逐窗校验恢复；若历史身份缺失或冲突，会停止并保留原结果，不把当前媒体冒充原媒体。没有完成切片的来源任务必须先恢复切片，不能将整片视频当作所选片段处理。旧格式片段和嵌套片段也保留原视频时间偏移。

从 OCR 结果选择「学习视频片段」会在保存媒体的对应切片上继续使用 OCR，保持裁剪和语言设置，不转换成平台字幕或音频转写。片段时间从 0 秒开始；原视频偏移会写入结果与笔记提示。低帧率录屏允许多个采样点落在同一帧的实际显示区间内，不会把一帧误当成只能对应一次抽样。

空结果、OCR 失败、解码中断和缺失时间戳不会被当作完整字幕，不会自动切换到音频转写或昂贵模型。部分结果可以查看和导出；只有完整完成且包含可用文字的 OCR 结果才能用于新笔记。所谓「抽样处理完成」只表示所有抽样窗口已处理，并不保证所有字幕已识别。

## 本地接口

- POST `/api/tasks/{source}/screen-subtitles`：`settings`、`generate_note`（默认 false）、可选 `options`。返回新的任务 ID。
- POST `/api/tasks/{source}/screen-subtitles/preview`：`settings`、`timestamp`。返回裁剪预览和逐行识别。
- GET `/api/tasks/{task}/screen-subtitles`：覆盖、错误、置信度和时间段结果。
- GET `/api/tasks/{task}/screen-subtitles/windows/{index}`：经过校验的完整窗口逐帧观察，包括空白、被筛掉的行、实际帧时间和逐行几何。
- POST `/api/tasks/{task}/screen-subtitles/resume`：使用原设置恢复。通用 `/resume` 也保持 OCR 路线。
- POST `/api/tasks/{task}/cancel`：沿用任务取消行为。

安装 `backend/requirements.ocr.txt` 后使用。解码支持不超过 3840×2160 像素的帧；更大的帧会明确失败，不会截断后声称完成。

## 可重现验收

`python -m unittest backend.tests.test_screen_subtitles backend.tests.test_screen_subtitle_recovery` 检查缓存、边界、队列恢复、媒体身份、损坏结果备份、片段归属、可变帧率、取消和禁止 ASR 降级。`node web/tests/screen_subtitles.test.mjs` 检查重复点击、关闭、切换和过期预览。

`python scripts/screen-subtitle-fixture-benchmark.py --output-dir build/screen-ocr-fixture` 在安装 Noto CJK 字体的 Linux 环境生成无音轨的 130 秒中英烧录字幕 MP4，运行真实解码与本地 OCR，半途中取消，再验证完整窗口复用和参数失效。每次使用新的输出目录。测试封锁 Python 外部网络并关闭 ONNX 原生遥测，使用安装包自带的本地模型；不使用真实用户视频。报告区分精确匹配与忽略空白的匹配，并保留实际识别文字。这些观测不代表真实长视频的准确率或耗时。
