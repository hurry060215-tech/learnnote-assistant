## B：可靠性与任务恢复

关联：#130、#131、#132。

### 当前实现和边界

- 60 分钟合成媒体/抽帧门禁不调用 ASR 或 LLM。
- 完整本地任务门禁使用本地确定性摘要夹具，报告明确 `remote_calls=0` 和 `api_key_configured=false`。
- 用户缺少模型时的真实任务仍保持失败状态，并保留字幕、草稿、检查点和诊断；不能把失败伪装成 AI 总结成功。
- 总结失败现在明确记录 `failed_phase=summarizing`。
- 上传过程同时受单文件上限、并发暂存预算、磁盘保留阈值和流式累计上限约束。
- 上传错误记录 `written_bytes`、`received_bytes` 和恢复建议；`pending_*`、`staged_*` 过期文件统一清理。
- 本地队列持久化任务意图，重型 worker 使用数据目录级租约；需要继续补充进程退出和 3–5 任务矩阵。

### 完成门槛

- 5/30/60/180 分钟输入和 3–5 个混合任务均有报告。
- 取消、进程退出、服务重启、断网和低磁盘条件下无任务丢失或重复执行。
- 重启可复用已有媒体、字幕和 checkpoint；需要重新授权的上下文必须显式提示。
- 所有失败报告包含阶段、错误码、资源报告和可执行恢复动作。

## D：站点权限与数据流

关联：#135。

### 当前实现和边界

- manifest 保留本地工作台 host 权限，站点访问使用 `optional_host_permissions`。
- 扩展发送前按当前站点请求权限，不在后台持续捕获页面媒体。
- 侧栏新增站点授权列表、撤销按钮和数据流说明。
- 撤销站点权限后清理该站点打开标签的内存候选、页面状态、捕获缓存和活动捕获 TTL。
- Cookie 只在需要重放当前来源时按站点和请求目标筛选；不持久化到扩展捕获缓存。

### 完成门槛

- Chrome、Edge 分别验证首次允许、拒绝、撤销和重新授权。
- 撤销后该站点不再接收新的捕获候选，旧缓存不会复活。
- UI 明确区分字幕、图片、Cookie、本地处理和外部模型调用的用途与去向。
- manifest、商店隐私说明、Dashboard 数据流说明和源码权限保持一致。
