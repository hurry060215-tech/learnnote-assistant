# LearnNote 核心架构审查与重构（2026-10-23）

审查基线是 GitHub `main` 的 `e9843a1456276d13b24785ebfd77f8c1f8f50fdc`。
开始时本地分支落后 105 个提交且工作区干净；本次分支从该主线建立。
范围是 LearnNote 仓库的实际产品路径：后端、当前阅读工作台、扩展、桌面启动与迁移、测试和发布。
没有把账户其他仓库纳入修改，也没有把 classic 界面的拆分量当成当前产品的收益。

## 判断

本地优先的 Python 后端、ES module 阅读工作台和按需浏览器扩展仍适合这个产品。
主要问题是职责重叠：查询负责修理状态、进度保存负责重建内容、列表负责判断实体存在、父进程退出被当成整项工作结束。
这些边界已经引起可复现的数据与交互问题，值得改变；重写语言或全面换框架没有相应证据。

基线后端含 208 个 Python 源文件、45,991 行，后端测试 44,759 行。
实际网页入口是 `web/index.html` / `web/desk.js`（当时 1,917 行），`web/app.js`（8,766 行）是 classic。
现有架构门禁能检查依赖和大小，但无法保证只读查询、队列 ownership 或 DOM 身份；本次增加行为验证。

## 已复现的问题与最终边界

| 问题 | 原行为 | 重构后的职责 |
| --- | --- | --- |
| 暂停排队被误判失败 | 7 小时无更新，读列表即改为 failed；启动恢复又将队列标 done | 列表单次只读；恢复服务持有执行 lease 并核对 generation 后裁决 |
| 无人负责的队首阻塞后续工作 | 任一 lane 忙就跳过全部启动恢复；遗留 callback 无人重建 | 分 lane 恢复；独立 OS owner lease 保护活跃 callback；持续观察繁忙或其他 owner |
| 进度反复重建全文 | 每次 `progress/message` 保存都读取正文和字幕、删除重插全部证据 | 持久化内容版本回执；未变内容只更新小目录行；内容、FTS、证据与回执同事务 |
| 全库列表放大磁盘读取 | 每 5 秒为每项构造完整媒体与证据详情 | 新 `/api/tasks/catalog` 仅投影 manifest 白名单；详情按选中 ID 读取 |
| 旧资料消失、错误宣称删除 | 后端最多取 500 行，前端再剔除任务关联资料；列表外 ID 当不存在 | 先过滤独立资料再 keyset 分页；所有标题可搜索；直接路由/引用按 ID 查询 |
| 刷新破坏正在使用的界面 | 相同快照重建列表与状态 DOM；旧操作响应抢走后续导航 | 无变化保留节点；事件按任务更新；异步完成必须仍拥有导航意图 |
| 取消后残留进程继续工作 | 只结束直接父进程，子孙继续运行 | Windows 启动前加入 Job；POSIX 独立进程组；成功、失败、超时、取消均回收树 |
| 本地与 PR 验证漂移 | 手工枚举部分入口和 desktop 测试 | 共享 JavaScript 检查入口；显式原生测试 gate；desktop 完整发现 |

扩展保留现有主动采集、来源身份、权限代次与不录屏边界。本次没有发现足以支持推倒这部分的缺陷。
使用者已有的私人笔记、资料、Cookie、API Key、模型请求和安装目录没有作为测试输入。

## 状态与数据兼容

- Task JSON 继续拥有任务事实，SQLite 队列拥有执行意图，catalog/FTS 是可重建投影。
- `list_tasks()` 不创建目录、修补标题或推断 worker 死亡；标题只在返回对象中规范化。
- `owner_id` 是随机实例标识，实际存活由 OS 文件锁证明；凭据和 callback 不写入队列。
  新列增加前执行既有一致性备份。旧行可恢复，但不承诺新旧二进制同时共享目录运行。
- 数据迁移识别精确新 schema。owner lock 目录不复制；仍有活跃 owner 时拒绝迁移。
- `task_projection_revisions` 是可丢弃的索引回执，不替代原文。旧库首次保存会建立回执。
  写入失败保留旧投影；下一次保存重试。缺失 FTS 在 savepoint 内从已有内容表完整回填。
  手动重建不信任旧回执；恢复 task index 会失效回执。
- 内容版本使用每次重新验证的归属、路径、文件身份、大小、mtime/ctime 和证据相关字段。
  这不是文件完整性认证：外部程序同大小原地编辑并刻意恢复全部可见属性时可能需要手动重建。
  正常任务原子发布、普通编辑、路径替换、删除和迁移均会重新建立投影。
- 原 `/api/tasks` 与单任务详情、任务 JSON、导出格式保持兼容；新摘要接口是显式新增契约。
  `/api/library/materials` 仅在 `standalone=true` 时使用分页，默认旧调用方式保持不变。
- 没有新增运行时依赖、浏览器权限、遥测、模型目的地或隐式网络请求，也没有版本升级或安装包发布。

`scripts/benchmark-task-index.py` 使用 1,000 段合成字幕、一份笔记、3 次纯进度更新。
同一 Python 环境分别运行基线归档与当前代码，得到：

| 指标 | 基线 | 重构后 |
| --- | ---: | ---: |
| 正文/字幕读取 | 6 | 0 |
| 全部任务证据删除 | 3 | 0 |
| 证据行重插 | 3,003 | 0 |
| 证据全文索引行重插 | 3,003 | 0 |
| 本机一次测量耗时 | 0.197214 秒 | 0.024743 秒 |

耗时仅代表该机器和合成案例，不是全应用性能承诺。工作量计数由真实 SQLite trace 和真实读取函数获得。
新 catalog 测试要求每条 manifest 只读取一次、零正文/媒体读取、零状态写事务。
