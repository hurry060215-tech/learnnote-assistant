# 扩展与本地工作台连接

## 0.2.9 客户端候选版

客户端 0.2.9 与扩展 0.2.8 使用同一协议。用户已将扩展提交 Google 审核，本轮客户端修复不要求重新上传或修改扩展。更新中心分别显示客户端与扩展版本，版本号不需要完全相同。

## 更新中心

在本机工作台的设置中打开“更新中心”。客户端和扩展会分别显示当前版本、正式频道版本和兼容状态。客户端更新默认在后台下载，只有点击“重启并更新”才会安装；有运行、排队、取消中的任务或未保存编辑时，安装会被拒绝。

商店版扩展由 Chrome / Edge 的更新生命周期管理，收到更新后按浏览器提示重新载入；浏览器节流时工作台只显示状态，不循环强制检查。受管理解压版使用客户端内置的固定 extension 目录，下载包会在本地二次校验，源码开发环境不会自动覆盖仓库；更新前保留旧扩展备份，应用后需要在扩展管理页重新加载。扩展偏好保留在浏览器存储中，连接中的任务不会因下载而被中断。

## 0.2.8 字幕预览与总结

客户端与扩展请使用同一版本。更新解压扩展后，在浏览器扩展管理页点击“重新加载”，再刷新视频页。

- “保存字幕原文”保存带时间点的逐字内容；“生成总结笔记”会调用文字模型生成要点和总结。
- 原文预览支持搜索、按停顿和段落长度分组、点击字幕定位视频。切换视频后不会把旧字幕跳转到新页面。
- av 和 BV 地址都支持主动字幕查询；“发现线索”不等于已取得完整正文。
- 工作台侧栏“我的”可查看个人主页与 Token 用量；已有字幕时无需下载本地语音模型。

## 0.2.7 模型、草稿与恢复

在本机工作台的模型设置中保存连接后，当前资料库的网页、桌面与扩展任务共用它。Key 不返回页面；Windows/macOS 使用系统凭据库，不可用时明确提示仅本次运行有效。连接按完整 API 地址绑定，已排队任务不会被重定向到后来选择的服务。保存失败会回滚凭据，清除连接不会令旧 Key 复活。

扩展显示当前模型与是否支持图像。明确的文字/图文任务缺少模型时，在下载或转写前停止；仅提取字幕仍可使用。模型名称对应的图像能力提示不代替供应商实际调用验证。

助手输入最多保留30份按来源区分的本机草稿。历史记录加载失败可重试；重新生成前保存上一份正文，在“历史版本”中查看、复制和下载。同步中断不会清空编辑输入。

扩展发送当前页面内容，本机 LearnNote 后端提供处理服务，工作台直接在浏览器中使用。Windows 和 macOS 的推荐入口分别是 `start-learnnote.bat` 与 `start-learnnote.command`；它们会等待 `/health` 就绪后再打开工作台。

- 打开工作台：优先使用当前浏览器中的本机服务；启动脚本会打开浏览器工作台页面。网页和扩展不能直接执行任意本地程序，所以首次使用请先双击对应平台的启动脚本。
- Windows `.bat` 和 macOS `.command` 都会在健康检查成功后再打开浏览器，避免先看到本机服务尚未启动的错误页；启动终端保持打开即表示服务仍在运行。
- 扩展依次检查保存地址、当前浏览器已打开的本机标签页地址和默认 8765；只接受带版本与协议标记的服务，不扫描任意端口。
- 不再依赖 `learnnote://` 协议或原生窗口聚焦；网页本身只访问本机 `127.0.0.1` 服务，不会执行任意本地程序。
- B 站首页推荐卡片不作为任务来源，请打开具体视频页面。未取得浏览器字幕不等于平台无字幕，发送后的标准处理仍先探测平台字幕。
- 已加载的解压扩展修改源码后，需要在浏览器扩展管理页点击重新加载。

验证：扩展与浏览器工作台回归继续覆盖本机服务连接；启动脚本会先等待健康检查，再打开浏览器，不依赖原生窗口或自定义协议。

## 0.2.4 的连续操作

- 点击发送时，有完整浏览器字幕就走字幕速记；无完整字幕的任务交接后，在工作台确认才开始探测和处理。
- 工作台导航使用 hash，打开设置或定位任务不会整页重载；当前输入和选中的资料保持明确。
- 外观设置在本机独立保存，即时预览，放弃修改会恢复；保存一个分类不会丢弃其他分类的草稿。
- 继续处理保留已有笔记。本地 ASR 缓存校验标准化媒体指纹、转写配置和字幕内容指纹，匹配才复用。改变来源或模型后重新识别。
- App 使用资料库级启动锁，重复双击复用实例；重启等待旧进程退出，启动失败提供可见提示。

此次 472 项后端、31 项网页模块与57项脚本回归通过；打包后的 Windows 0.2.4 通过设置、助手、产品工作台与工具流程的浏览器验收。登录站点字幕、真实远程模型、签名安装升级不属于这些模拟与本地验收的通过结论。

## 0.2.5 字幕与账号连接

标准整理会先取得平台或播放器字幕，可用时跳过视频下载、音轨转写与画面处理。需要图文或 OCR 时仍按用户选择获取视频。B 站扩展主动查询当前分 P 的字幕，不保留监听器；字幕不存在、鉴权失败和探测不可用分别处理。

`POST /api/tasks/{id}/retry-summary` 只复用任务所属字幕，重新生成总结；不会再下载、转写。之前生成的正文保存在任务目录 `summary_versions`，个人编辑稿继续独立保留。失败候选正文在任务的 `vision_cache/rejected-summary.md`，处理记录与失败原因从界面可下载。

`GET /api/model/providers` 提供服务商和认证方式；`POST /api/model/setup/check` 支持短对话或模型列表验证。OpenRouter 通过 `/api/connections/openrouter/start` 启动其官方 PKCE 授权，回调绑定同一浏览器、随机 state 和十分钟有效期。凭据仅发给精确的 OpenRouter API 地址；Windows/macOS 使用系统凭据库，其他本机平台仅保留本次服务会话。断开连接删除本机授权副本，不等于撤销供应商账户内的 Key。MiMo 使用其官方 API Key 接口，不提供不存在的 MiMo OAuth。

官方认证文档：https://openrouter.ai/docs/guides/overview/auth/oauth ；MiMo：https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call 。

本轮真实 MiMo 验收使用已有酒店视频音频转写生成六节主题总结，不重新获取视频；自动回归使用隔离资料或模拟服务，不等同于真实网站登录态字幕验证。
