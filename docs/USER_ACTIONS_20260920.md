# 需要用户完成的外部事项

本文件只列开发与自动化无法代替的条件；代码、测试、文档和符合条件的 PR 合并继续由代理处理。商店仅为 Google Chrome Web Store。

1. **Google 商店账号与条目**：在 Chrome Web Store Developer Dashboard 完成开发者注册和所需验证，创建 LearnNote 条目；提供 publisher ID、item ID。令牌不要发到聊天，按 docs/BROWSER_STORE_SUBMISSION.md 配置到仓库 Secrets。实际上传/提交审核仍需单独明确指令。当前无已核验正式 listing。
2. **Chrome 原生权限操作**：需要在独立测试配置执行允许、拒绝、撤销、重新授权，并验证重新启动后状态。上次 Windows 电脑操作工具因无法识别浏览器 URL 而停止；自动化竞态测试已通过，但不能代替原生弹窗验收。此项不阻塞后端工作。
3. **真实登录态来源**：提供愿意用于验收的 B 站课程链接，在本机自行登录；不发送 Cookie、密码或验证码。只验证可访问内容，不绕过付费或 DRM。
4. **真实模型验收**：确认使用哪个已配置模型、是否允许真实调用及可接受费用上限；密钥在客户端本机设置，不发到聊天。无 Key 和离线降级测试不依赖此项。
5. **Word/WPS**：Word 可用性可由本机检查；若要求 WPS 实机通过，需要可运行的 WPS。最终请打开提供的 30+ 页样例核对分页、字体、公式和来源链接，标记具体页码。
6. **macOS**：提供可用 Mac 或由你按验收清单执行原生安装、凭据保存、迁移、升级回退与扩展连接。当前 Windows 主机不能提供 macOS 实机证明。签名/公证需要相应 Apple 开发者条件。
7. **Windows 签名与正式发布**：若要求受信任签名，需要证书或签名服务；通过安全凭据配置提供，勿发送证书密码。未具备前维持未签名及校验和说明。正式发布另行授权。

目前不需要你手工删分支、删数据或整理缓存；所有现有配置、课程资料、登录态和历史证据继续保留。
